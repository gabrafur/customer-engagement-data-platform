# Data model

The domain models are intentionally compact and synthetic. The diagram includes both the
default local runtime objects and the separately modeled outbox pattern.

~~~mermaid
erDiagram
    CUSTOMER ||--o{ TRANSACTION : places
    CUSTOMER ||--|| CUSTOMER_FEATURES : produces
    CUSTOMER ||--o{ RECOMMENDATION : receives
    RECOMMENDATION ||--o| DELIVERY_RECEIPT : returns
    RECOMMENDATION ||--o{ OUTBOX_EVENT : may_enqueue
    OUTBOX_EVENT ||--o{ OUTBOX_TRANSITION : records

    CUSTOMER {
        string customer_id PK
        string region
        string segment
        date registration_date
        double engagement_score
    }
    TRANSACTION {
        string transaction_id PK
        string customer_id FK
        string product_id
        date transaction_date
        double amount
    }
    CUSTOMER_FEATURES {
        string customer_id PK
        int customer_age_days
        int days_since_last_transaction
        int purchase_frequency
        double average_order_value
        double engagement_score
    }
    RECOMMENDATION {
        string recommendation_id PK
        string customer_id FK
        string region
        string recommendation_type
        double score
        int regional_rank
        string idempotency_key UK
        timestamp created_at
    }
    DELIVERY_RECEIPT {
        string idempotency_key PK
        string state
        int status_code
        int attempts
        timestamp delivered_at
    }
    OUTBOX_EVENT {
        string event_id PK
        bigint sequence
        string idempotency_key
        string payload
        timestamp created_at
    }
    OUTBOX_TRANSITION {
        bigint sequence PK
        string idempotency_key
        string state
        timestamp occurred_at
        string detail
    }
~~~

## Runtime and persistence boundaries

- Immutable dataclasses in [models.py](../src/engagement_platform/models.py) define customers,
  transactions, features, recommendations, and delivery receipts used by the local pipeline.
- [outbox.py](../src/engagement_platform/outbox.py) defines append-only events and transition
  history as an independently tested reliability pattern.
- [create_demo_tables.sql](../sql/create_demo_tables.sql) defines generic Delta tables for
  customers, recommendations, outbox events, and transitions. The local CLI does not execute
  this DDL or persist every runtime object.
- [storage.py](../src/engagement_platform/storage.py) persists recommendations either in
  memory or through the optional Delta adapter.

Every sample row is hand-authored or generated by
[synthetic.py](../src/engagement_platform/synthetic.py). Identifiers, dates, amounts,
categories, and rules are fictional.
